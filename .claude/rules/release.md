# CI and releases

CI (`.github/workflows/ci.yml`) runs fmt, clippy and the tests in parallel jobs on Linux, and on an Apple silicon Mac clippy and the tests' build in one job, whose archive two jobs then test half each (three macOS jobs a run, since the account runs few at once and the whole suite on one Mac was slow and timed out screen waits), the tests through cargo-nextest on 8 threads (the Linux job checks that nextest lists every test `cargo test` does); Intel Macs are built only by the release; each job's cache of the dependencies' builds is saved again whenever the toolchain, `Cargo.lock` or the profiles change. Each test binary links every crate, so the target directory is large: debug builds keep only line tables (the dependencies at opt-level 1, since the tests spend their time in alacritty_terminal and ratatui, and the crate's own code at 0, so its incremental builds stay quick), and a worktree's build should not leave extra copies of `target/` about.

A release is a version bump on main: bump `Cargo.toml` in a commit of its own (`cargo check` updates `Cargo.lock`), and once that commit is on main `.github/workflows/release.yml`, finding no release of that version, builds it, signs each archive with the release key, tags it `v<version>` and publishes the release, with the `install.sh` of the commit released beside the archives, signed (in a namespace of its own, `switchboard-installer`) and with its checksum, which is the one the README installs from (`releases/latest/download/install.sh`), never `main`'s; `install.sh` installs the binary and leaves `switchboard setup` as a step of its own, unless `SWITCHBOARD_SETUP=1` is set. Switchboard is under the MIT license (`LICENSE`, and `license` in every crate's manifest). The key's private half is the `RELEASE_SIGNING_KEY` secret of the repository's `release` environment (an OpenSSH Ed25519 key, unencrypted), which only `main` may deploy from, and never a repository-wide secret, since only the environment keeps it from a workflow someone rewrote on another branch; and its public half is in `src/update/release-signing-keys.pub`, which the binary compiles in, and in `install.sh`'s `RELEASE_KEYS`, which a unit test keeps the same; a run without the secret, or with a key not listed there, fails before publishing. `switchboard update` offers only the newest release, so a binary trusts only the keys it was built with: replace the key only when it is lost or leaked, by listing the new public key beside the old one (in the installer checks the README and the diff's and Notes' READMEs show too, one `allowed_signers` line a key, which a unit test keeps listing every key), releasing with the old, then signing with the new, and know that a binary which skipped that release refuses every one after it, so its user installs again with `install.sh`, which carries the new key. So the bump's commit is the release: pushing or merging it publishes, and is asked about as the push to main it is. The version bumped is the workspace's (`[workspace.package]`, the first line of `Cargo.toml` that sets a version, which the workflow reads).

The diff releases apart from Switchboard, by the same rule: a bump of `crates/diff/Cargo.toml`'s version in a commit of its own, once on main, makes `.github/workflows/release-diff.yml` build `switchboard-diff` alone, sign `switchboard-diff-<version>-<target>.tar.gz` for each target with the same key in the same `release` environment, tag it `diff-v<version>` and publish it, never as the repository's latest release, which stays Switchboard's (`install.sh` reads that one, and `switchboard update` reads only `v<version>` tags). So that bump is a release too, asked about as the push to main it is. A version ending `-dev` is never released, which is how the crate sits between releases; `install.sh --diff` installs the newest `diff-v` release, and `switchboard-diff update` a newer one over it, the workflow building with `SWITCHBOARD_RELEASE` set so only a release looks for one by itself. Notes releases the same way: a bump of `crates/notes/Cargo.toml`'s version makes `.github/workflows/release-notes.yml` publish `switchboard-notes-<version>-<target>.tar.gz` under `notes-v<version>`, which `install.sh --notes` installs, so that bump is a release too. A tag pushed by hand releases nothing: the workflow runs only for main.

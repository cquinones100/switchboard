# Settings and the files of your own

**Settings.** Every option is in `assets/settings.json`, with its key, category, label, description and default (on/off, or one of its `choices`); what someone changes is kept in `~/.config/switchboard/settings.json`, only the keys that differ from their defaults, which they may also edit by hand. `src/settings.rs` reads it (`settings::is_on`, `settings::setting`) and writes it (`write_setting`), never over a file it can't read as a JSON object, keeping the version before as `settings.json.bak`; the server reads it again whenever it changes. A new option is one entry there and the code that reads it; its description says what it does now, and what turning it off does. An option of one mission control view goes in that view's category, `Mission control: <view>`, after the view's on/off switch, which leads it: a category named `group: name` is drawn under its group's heading in Settings (`settings::categories`), and "Mission control" itself keeps only what belongs to every view. Every new feature gets one, on by default unless it sends something of yours somewhere (as the todo note routine sends your notes' items to Claude), so each part can be turned off for a plain workspace: a view, a sidebar block, a background check, a key that changes what an existing one does. A new view with a setting goes in `src/usage/habits.rs`'s `VIEWS`, and a feature worth suggesting in `TRIES`.

**The user layer.** Every file of someone's own lives in `~/.config/switchboard/` (or, with Settings' `files_from_repo` on and `files.json` naming a git repository, in the folder of its clone under `~/.local/share/switchboard/files`, which `src/files` pulls, and pushes as it changes, after `leak-check` and a question about anything it finds), never in this repository, and nothing writes over one but Settings: `settings.json`, `keys.json` (bindings over the defaults), `sidebar.json` and `sidebar-plugins/`, `browser.json`, `linear.json`, `claude.json` and `CLAUDE.md`, `slack-updates.json`, `slack-relay.json`, `oncall.json` and `oncall-rules.md`, `repos.json`, `files.json`, `leak-check.txt`, `trusted-dirs`, `autopilot-claim.json`, and `secrets.json` where Linux has no keyring. Code reaches one through `paths::config_dir()`, which is the clone's folder while the files come from a repository, never a path of its own; `files.json`, `trusted-dirs`, `repos.json`, `sidebar-plugins/`, `slack-relay.json`, `linear.json`, `oncall.json`, `oncall-rules.md`, `slack-updates.json`, `autopilot-claim.json` (autopilot's claim ID, each computer's own), `secrets.json`, `leak-check.txt`, the `.bak` copies and the `files_from_repo` setting itself (`files::LOCAL`, `settings::LOCAL`) never leave the computer, so they are read through `paths::local_config_dir()` (or `files::file`), and a new file that decides what code runs with no one asked, names who Switchboard answers to, holds a secret or is read by a skill by its path goes there too. Each setting in one has a row in mission control's Settings view, from `OWN_FILES` in `src/usage/own.rs`, so a new setting in a file there, or a new file, gets an entry there and a row in the README's and the guide's tables. No one's own rules live here: what every user's Claude needs to know about the workspace goes in `assets/switchboard.md`, which `switchboard setup` imports into `~/.claude/CLAUDE.md`.
